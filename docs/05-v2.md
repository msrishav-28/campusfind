# V2 — why it exists, what it is

V2 exists only if v1 is alive: found pins every day, claims happening, the map trusted.

V1 answers: *will someone standing on Kengeri pin a found item in 20 seconds?*
If that fails, more features will not save it.

If it works, three problems appear:

1. **Volume** — 40 open pins. Need matches and notifications.
2. **Place depth** — “Block IV” is too coarse. Floor and a path.
3. **Operations** — desk, hostels, a second CHRIST campus.

## V1 must already have proven

- Found posts without nagging
- ≥80% photos, ≥95% coordinates
- Claims use the private detail
- Pins expire
- Share links are how WhatsApp points at items

## In v2

1. **Matching and alerts** — vision tags (if not already in v1.1), ranked possibles, Web Push or a notify link. Human confirms. No auto-close. No 92% badge.
2. **Deeper map** — real floor chips, better footprints, `Navigate` deep-link into `campus-nav-3d`, optional door QR. Not 3D inside this app. Not beacons.
3. **Desk as a role** — received / returned / disposed, QR on the desk, campus RLS. Still student-run framing until a MoU.
4. **Second campus** — walk Central or BGR, `/central`, same code. No all-CHRIST mega-map.
5. **Hygiene** — ID blur, report thresholds, meet-spot defaults, 90-day photo retention.

## Order inside v2

1. Tags + match list + notify
2. Desk workflow
3. Footprints / floor / nav link
4. Door QR
5. Second CHRIST campus

Stop after (1) if matching is unused — the map is still small.

## Not v2

Chatbot intake, native apps, points, city-wide L&F, self-serve tenants, auto-approve claims, BLE, Wi-Fi RTT.

## Split

- **V1** — make the pin real.
- **V1.1** — file the card and retrieve three matches.
- **V2** — notify the owner, run a desk, open the next campus.
- **V3** — other universities, 3D in the walk, maybe native.
